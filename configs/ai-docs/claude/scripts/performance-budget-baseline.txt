# performance-budget-baseline.txt - the performance budgets
# check.sh already reports as over, and the value each one measured when
# the regression gate (check-performance-budget-regressions.py) was
# introduced.
#
# This is DEBT, not permission. Every line is a budget someone has to
# bring back under its cap; nothing here is an accepted exception. The
# gate exists because check.sh had no caller at all, so two budget
# regressions shipped with the whole harness green. Enforcing all of
# these at once would have turned run-tests.sh red for every session in
# this tree, so the bleeding is stopped first and the debt is drained
# after.
#
# The gate fails on a key that is absent here, and on a key whose
# measured value has grown past the value recorded here. It stays green,
# and prints a tighten-the-baseline notice, when a value shrinks or an
# entry stops being reported at all.
#
# TO UPDATE: only ever downward. When the notice says a budget improved,
# lower that line's value to the new measurement; when it says one
# resolved, delete the line. Never raise a value and never add a line to
# make the gate green - that is silencing the check, and the fix is the
# overage itself. There is deliberately no regenerate flag.
#
# Each entry reads `<report section> :: <what was measured> :: <metric>
# = <value>`, taken verbatim from check.sh's own report. Lines starting
# with # are comments; blank lines are ignored.
